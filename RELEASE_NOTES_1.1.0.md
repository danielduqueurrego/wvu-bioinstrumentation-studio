# WVU Bioinstrumentation Studio 1.1.0

This release adds LED-sequenced pulse oximetry, so a pulse-ox photodetector and other analog signals can be recorded in one lab. It builds the Op Amp Lab into the application, lets students install a lab file from their instructor, and redesigns the main window around one recording bar and one message at a time. Every recording is now finalized, however it ends. The bundled Arduino tools move to the stable Arduino CLI 1.6.0, and the boards get new WVU firmware, build `0x00010007`.

**Download** `WVU_Bioinstrumentation_Studio_1.1.0_x64-setup.exe` for students and most lab computers, or `WVU_Bioinstrumentation_Studio_1.1.0_x64.msi` for managed IT deployment. `SHA256SUMS.txt` lists their checksums. `WVU-Bioinstrumentation-Studio-1.1.0-Windows-x64.zip` holds both installers with the Student Quick Start, these notes, and the license and notice files.

## Before you install

- **First update every computer that connects to the course boards, then restore each board once.** That includes lab computers, instructors' laptops, and students' own installations: have students install 1.1.0 before the boards are restored. This version needs WVU firmware build `0x00010007`. A board restored by 1.0.x shows **Older WVU firmware** until you select **Restore WVU Firmware** once. A computer still on 1.0.x reports a restored board as **Firmware update required** and suggests **Restore WVU Firmware**: do not restore there, because that puts the old firmware (build `0x00010006`) back on the board. Update that computer instead. From this version on, a computer whose app is older than the board's firmware says **Newer WVU firmware**: update that computer.
- **Updating from 1.0.x.** Run the 1.1.0 installer of the same type as before (NSIS setup over NSIS, MSI over MSI). It is designed to remove 1.0.x first, so Installed apps keeps one entry. The publisher shown in Installed apps changes from `wvu` to West Virginia University Department of Chemical and Biomedical Engineering. The NSIS setup keeps the 1.0.x installation folder, including a custom one; the MSI installs into the default Program Files folder, even when 1.0.x was installed elsewhere. If the setup says "Unable to uninstall", uninstall 1.0.x from Installed apps and run the setup again.
- Project folders, recordings, calibration presets, and local labs are stored per user and are kept. The first start may show **Preparing Arduino tools…** once.

## New

- **Pulse oximetry with other analog signals.** The board steps the LEDs RED, DARK 1, IR, DARK 2, and at the end of each state it reads every input of the lab (one to six of A0–A5). The CSV has one row per LED state, with `led_state` (0–3) and `led_state_name` (`RED`, `DARK1`, `IR`, `DARK2`). **Show by LED state** draws a signal as four traces, one per state; it changes the display only.
- **Pulse Oximetry — TX + RX Raw Capture 1.1.0** uses this mode: TX on A0, RX on A1, D5 red, D6 IR, 1000 rows/s (250 per LED state). The previous version, 1.0.0 (legacy four-state mode), is `profiles/legacy/pulseox_tx_rx_course_capture_1.0.0.profile.json` in the repository. To go back, install it with **Install lab file…**; **Restore course default** returns to 1.1.0. A computer where an instructor made an edited pulse-ox lab active keeps it, in the legacy four-state mode, until the instructor selects **Restore course default**. Labs are stored per Windows account, so **Install lab file…** and **Restore course default** change only the account they are used in: each student account needs them ([Push a lab to students](https://github.com/danielduqueurrego/wvu-bioinstrumentation-studio/blob/v1.1.0/docs/INSTRUCTOR_GUIDE.md#push-a-lab-to-students)).
- **Op Amp Lab is built in:** Vmid on A0 and Vout on A1 at 100 frames/s, listed beside General Analog. Its CSV columns are `vmid_counts`, `vmid_V`, `vout_counts`, and `vout_V`. The old Op Amp Lab copy from the 1.0.2 installer wrote `a0_counts`, `a0_V`, `01_counts`, and `01_V`, so update spreadsheets or scripts that use those names; recordings already made are unchanged. The separate Op Amp Lab installer from 1.0.2 is retired; do not run it.
- **Install lab file…** in the Lab card installs a `.lab.json` file from the instructor, after showing the lab and asking. An instructor's first edit of General Analog is now 2.0.2: 2.0.1 belongs to the old Op Amp Lab copy, which stays (retired) on computers that ran the 1.0.2 installer. **Save as course default file…** in Manage Labs writes a lab file for the next application build; it is for maintainers, not students.
- **Redesigned main window:** a recording bar that stays at the top, a checklist of what Start still needs, one message with one next step, and collapsible setup cards. The Board card has a status chip, and **Restore WVU Firmware** opens a step-by-step window with a 90 s countdown for the double reset. The **Last recording** card shows which files were saved, with **Copy path** and **Show in folder**. Live signals add **Pause display**, time-window buttons, labelled marker lines, and a **SIMULATED DATA** watermark.
- **Source** still starts on **Simulator (practice)**, and now switches to **Hardware** once, the first time the firmware on the selected board is verified ready, unless the student has already chosen a Source.
- **Older WVU firmware** and **Newer WVU firmware** replace the general incompatible-firmware message when a board runs another build of the WVU firmware.

## Changed and fixed

- **Recordings are always finalized**, whatever ends them. The raw `.bmeg` file and the metadata are saved before the CSV, a disk-write failure ends the recording as a fault instead of abandoning the file, existing files are never replaced, and raw data are never deleted. Labs without LED outputs, such as ECG, EMG, and General Analog, no longer lose the data still on its way from the board at Stop.
- **Arduino CLI 1.6.0**, the stable release, replaces the 1.5.2 release candidate. OpenOCD and dfu-util are no longer included; the UNO R4 WiFi never used them.
- **Firmware restore works on Windows accounts with long profile folder names** (more than 24 characters), where 1.0.x fails with a compiler error. The Arduino tools are then kept in a folder under `%ProgramData%` that only that account (and administrators) can open, so IT policies must let standard users create folders there; if they cannot, the Board card says so. These folders (about 700 MB each) stay after the app is uninstalled or the Windows account is deleted; an administrator can delete them.
- **Firmware timing and safety:** in both pulse-ox modes, each reading is taken at least half a dwell after the LEDs change, even when the board falls behind, and LED states are never skipped or reordered. A hardware watchdog restarts the board if its program stalls, and the restart leaves the LED outputs off. In labs that are not pulse-ox labs, the firmware refuses to switch on D5 (red) or D6 (IR); only D4 can be on. At Stop, the app repeats the stop command if the board does not answer, so the LEDs turn off without waiting for the firmware's 5-second timeout. Skipped sampling deadlines are counted in the recording metadata.
- **Computers that ran the 1.0.2 Op Amp Lab installer:** on the first start, the old Op Amp Lab copy, which had replaced General Analog, is retired, and General Analog is back in the Lab list. A backup of the lab list is saved first, and the Lab card says so, with the backup's location. This happens once.
- Board actions (Verify, Retry connection, Restore) no longer freeze the window. Restore is refused while more than one UNO R4 WiFi is connected. A COM port held by another program is reported as busy and does not change the firmware result.
- The storage check includes room for the CSV, Windows stays awake during a recording, and changing the lab no longer loads the previous lab's calibrations.

## Known limitation

- **LED-sequenced labs with more than two channels need a dwell of at least 2000 µs.** While the board sends data over USB, it sometimes takes a reading late. The next reading is on time again, and nothing is lost or mislabeled: every reading stays in its LED state at least half a dwell after the LEDs change, and `t_us` holds its measured time. With the built-in pulse-ox lab (two channels, 1000 µs), this happens about once a second, by up to about 0.5 ms. With three to six channels at 1000 µs, it happens after most groups of ten rows and sometimes lengthens a state. For such labs, set **State dwell** to 2000 µs or more (500 rows/s, 125 per LED state); six channels at 2000 µs were tested on hardware. See [Hardware](https://github.com/danielduqueurrego/wvu-bioinstrumentation-studio/blob/master/docs/HARDWARE.md#pulse-oximetry).

## Third-party source code

The source code of the GPL and LGPL tools in the bundled Arduino runtime is attached to this release as `WVU-Bioinstrumentation-Studio-1.1.0-third-party-sources.zip`, with its `.sha256`. The bundle for versions 1.0.0 to 1.0.2, `WVU-Bioinstrumentation-Studio-1.0.x-third-party-sources.zip`, is attached to the v1.0.0, v1.0.1, and v1.0.2 releases. The installed application lists every bundled component, its license, and its source in `BUNDLED_COMPONENTS.txt` in the `resources\licenses` folder of the installation folder, beside `LICENSE.txt` and `NOTICE.txt`; the Windows ZIP also includes `THIRD_PARTY_NOTICES.md`.

Requirements remain Windows and Arduino UNO R4 WiFi. This build uses firmware protocol `0.4`, reference firmware build `0x00010007`, Arduino CLI `1.6.0`, and Arduino Renesas UNO core `1.6.0`.

Teaching use only — not a medical device. Follow BMEG 420L lab instructions and instructor safety procedures. Do not use this software for diagnosis or clinical decisions.
