WVU Bioinstrumentation Studio bundled-component notice

This directory accompanies the app's pinned offline Arduino runtime,
resources\arduino-runtime.zip: bundle revision 4, Arduino CLI 1.6.0 and the
Arduino UNO R4 core 1.6.0. The app extracts the archive to
%LOCALAPPDATA%\WVU-BMEG\rt (or, when that path is 60 characters or longer,
to %ProgramData%\WVU-BMEG-<user id>\rt) and runs the tools from there. Each
"Path" below is relative to the archive root, which is the same as that
folder.

Corresponding source: each release that carries this runtime publishes
WVU-Bioinstrumentation-Studio-<version>-third-party-sources.zip (for example
WVU-Bioinstrumentation-Studio-1.1.0-third-party-sources.zip) beside its
installers on the project's GitHub Releases page:
https://github.com/danielduqueurrego/wvu-bioinstrumentation-studio/releases
It holds the source of every GPL- and LGPL-licensed component below (with
the Go module dependencies of the Go programs and the libraries the
toolchain links statically), the BOSSA license, a README.txt with build
directions and a written offer, and SHA-256 sums. To ask for source, or to
report something missing, open a "Request corresponding source" issue:
https://github.com/danielduqueurrego/wvu-bioinstrumentation-studio/issues/new?template=source_code_request.yml

The archive root keeps the Arduino CLI release's own LICENSE.txt as
arduino-cli-LICENSE.txt (GNU GPL version 3), and copies of the GNU GPL
version 2 (GPL-2.0.txt) and GNU LGPL version 2.1 (LGPL-2.1.txt). The other
upstream license and notice files stay in place inside the archive.

No longer included (removed in runtime revision 4)
  OpenOCD 0.11.0-arduino2 (GPL-2.0-or-later) and dfu-util 0.11.0-arduino5
  (GPL-2.0-or-later) were in data/packages/arduino/tools/ of runtime
  revision 3, which versions 1.0.0 to 1.0.2 carried. The UNO R4 WiFi never
  uses them: it uploads with bossac, and this version does not include
  them. The source that is available for them, as far as Arduino has
  published it, is listed in release/third-party-sources-runtime3.json in
  the project's source repository; ask for it, or for the rest, through the
  "Request corresponding source" issue form above.
